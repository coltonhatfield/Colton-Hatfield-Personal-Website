Model card

How the calculator works

One scenario, 20,000 possible worlds

Each run samples five attacker-cost buckets, ten conditional attack stages, monetizable value, payment, and recovery cost. A fixed seed makes the same inputs reproducible.

Core equations

TEAC = P + A + C + E + RP(success) = ∏ P(stageᵢ | prior stages, attacker, defender, cohort)Expected attacker proceeds = P(success) × monetizable valueExpected loss per attempted scenario = P(success) × loss if successful

Cohort scaling

Revenue and employee count alter access, execution, monetization, and recovery distributions with deliberately modest elasticities. These elasticities are scenario assumptions because public incident-level datasets are not sufficient to estimate a general company-size equation. The exported assessment records them.

What controls do

Controls modify relevant stage probabilities and, where economically coherent, attack cost or monetizable value. A shared posture factor also introduces dependence between stages. Effect sizes are transparent modeled assumptions—not causal claims.

Interpret carefully

The model asks whether a specified attack path looks economically attractive under uncertainty. It does not estimate annual breach frequency, predict a named actor, or produce a validated organization-specific risk score.
